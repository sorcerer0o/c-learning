二、多端同步方案 (解决 WSL + Windows + VM 不连续问题)
===============================================================================

  2.1 问题分析

    你有三个环境:
      A. Windows 主机 (VS, VS Code, 资料存放)
      B. WSL Ubuntu   (日常开发, Neovim)
      C. VM 虚拟机    (Linux 环境)

    资料在 Windows: C:\Users\sorcerer\Wangdao\materials\
    笔记在 WSL:     ~/notes/c-learning/
    代码在 WSL:     ~/projects/
    这导致三端不同步, 编辑器和文件都割裂。

  2.2 推荐方案: Git 中心化

    WSL (开发主力)
      笔记 (notes/c-learning/)
      代码 (projects/ 或 code/c/)
      Neovim 配置 (.config/nvim/)
      tmux 配置 (.tmux.conf)
      .bashrc 等
      |
      |-- git add && git commit && git push
      v
    GitHub / Gitee (私有仓库)
      |
      |-- git pull
      v
    VM 虚拟机 (同步)
      同样的笔记和代码

    Windows 侧:
      通过 \\wsl$\Ubuntu\home\sorcerer\notes\ 直接读取 WSL 文件
      或通过 git pull 到 Windows 目录

  2.3 不推荐的做法

    X  在 /mnt/c/ 下直接开发 (跨文件系统, 性能差)
    X  用 U 盘手动拷贝
    X  依赖云盘同步 (权限/符号链接问题)

  2.4 实操步骤

    初始化 WSL 仓库:
      cd ~/notes/c-learning
      git init
      git add .
      git commit -m "init: c learning notes"

      cd ~/projects
      git init
      git add .
      git commit -m "init: c practice code"

    推送到远程:
      # GitHub/Gitee 上创建私有仓库
      git remote add origin git@github.com:yourname/c-learning.git
      git push -u origin master

    VM 上同步:
      git clone git@github.com:yourname/c-learning.git ~/notes/c-learning
      git clone git@github.com:yourname/c-projects.git ~/projects

  2.5 日常同步命令

    # 开始工作前
    git pull

    # 工作结束后
    git add -A
    git commit -m "DayXX: 完成了XXX"
    git push

  2.6 关于 VM

    如果你只是为了学 Linux:
      WSL2 已经够用, 不需要单独的 VM
      省掉 VM = 少一个要同步的环境

    如果 VM 是课程强制要求:
      同上 git 方案, 两边各拉各的

三、编辑器统一方案
===============================================================================

  3.1 原则: 各司其职, 不要强求统一

    不同阶段用不同工具, 工具服务于学习目标:

    学习阶段        推荐编辑器        原因
    -----------    -------------     ------------------------
    初学基础        VS (Windows)     调试器最强, 可视化管理
    (Day00-05)      VS Code + WSL    图形化, 熟悉 Linux 编译

    指针/字符串     Neovim (WSL)     轻量, 练 Vim 手感
    (Day06-09)      GDB (WSL)        调试 C 程序

    数据结构/算法   Neovim + GDB     纯终端, 效率最高
    (Day10-17)      VS Code (可选)   需要时切

    Linux 编程      Neovim + GDB     Linux 标配
    (Day18-25)      VS Code (可选)   备选

  3.2 编辑器选择策略

    VS:
      - 什么时候用: 需要单步调试, 看内存窗口, 监视变量
      - 优势: 调试功能最强 (断点/监视/调用堆栈/内存)
      - 劣势: 只在 Windows, 重, 不能用在 WSL/VM

    VS Code:
      - 什么时候用: 偶尔想用图形界面, 或需要 Remote-WSL
      - 插件: C/C++ (Microsoft), Code Runner, GitLens
      - WSL 连接: Ctrl+Shift+P -> Remote-WSL: Open Folder in WSL

    Neovim (推荐主力):
      - 什么时候用: 日常写代码, 所有 C 代码
      - 优势: 轻量, 终端内, 配置可跨平台 (WSL/VM 一致)
      - 劣势: 学习曲线

    Vim (原生):
      - 什么时候用: 快速改文件, SSH 远程, 服务器
      - 够用即可, 不用配插件

  3.3 Neovim 配置统一 (WSL + VM 一致)

    在 WSL 上配好, git 管理, VM 拉下来直接复用:

    # 安装 Neovim
    sudo apt install neovim

    # 配置目录
    ~/.config/nvim/
    |-- init.lua          主配置
    |-- lua/
    |   |-- plugins.lua   插件管理
    |   |-- keymaps.lua   快捷键
    |   |-- lsp.lua       LSP 配置

    # 用 git 管理配置 (dotfiles 仓库)
    cd ~/code/dotfiles
    mkdir -p nvim/.config/nvim
    cp -r ~/.config/nvim/* nvim/.config/nvim/
    git add . && git commit -m "init: neovim config"

    VM 上:
    git clone git@github.com:yourname/dotfiles.git ~/dotfiles
    cp -r ~/dotfiles/nvim/.config/nvim ~/.config/

    推荐的 Neovim 插件 (C 开发):
      - nvim-lspconfig    + clangd      代码补全/跳转/诊断
      - telescope         文件搜索/符号搜索
      - treesitter        语法高亮
      - gitsigns          git 状态
      - which-key         快捷键提示

  3.4 编辑器的阶段过渡

    第一阶段 (Day00-05):
      VS 写代码 + VS 调试
    第二阶段 (Day06-12):
      VS 调试 + Neovim 写代码
    第三阶段 (Day13-25):
      Neovim 写代码 + GDB 调试
    第四阶段 (毕业后):
      Neovim + GDB, 回到 VS Code 看图

四、每日标准工作流
===============================================================================

  以下是你每天应该执行的标准化流程:

  4.1 晨间 (5 分钟)

    [ ] 打开 WSL 终端
    [ ] cd ~/notes/c-learning   (笔记目录)
    [ ] git pull                 (拉取最新, 多端同步)
    [ ] vim 00_idex/README.md    (打开本计划, 看今日任务)

  4.2 上午: 学习新知识 (1-2 小时)

    [ ] 打开今日笔记: vim noters/dayXX.md
    [ ] 通读笔记, 理解每个知识点
    [ ] 对照思维导图 (如果有) 梳理知识结构
    [ ] 在笔记中遇到不理解的地方, 回到对应的预习 PDF 查阅
    [ ] 用 VS 或 GDB 验证代码示例

  4.3 下午: 动手写代码 (1-2 小时)

    [ ] cd ~/projects/DayXX      (进入今日代码目录)
    [ ] 创建文件: vim main.c
    [ ] 完成今日练习 (详见第6部分每日计划)
    [ ] 每道题手写, 不要复制粘贴, 不要问AI
    [ ] 编译: gcc main.c -o main -Wall -Wextra
    [ ] 运行验证: ./main

  4.4 调试 (30 分钟)

    [ ] 如果程序崩溃/结果不对, 先用 GDB 或 VS 调试
    [ ] 断点 -> 单步 -> 观察变量 -> 找到问题
    [ ] 尽量不要问 AI, 自己找 bug
    [ ] 解决后在 盲点.md 记录 (下次注意)

  4.5 晚间: 复习 (30 分钟)

    [ ] 打开今日笔记, 盖住内容, 看标题回忆
    [ ] 模糊的地方重新看一遍
    [ ] 执行艾宾浩斯复习 (看第五部分)
    [ ] 复习完成后, 在笔记末尾的复习记录打勾

  4.6 收尾 (5 分钟)

    [ ] git add -A
    [ ] git commit -m "DayXX: 完成了XXX, 复习了DayYY"
    [ ] git push
    [ ] 关闭终端

  4.7 周末检测 (每完成一个 Phase)

    [ ] 打开该 Phase 的阶段检测
    [ ] 不看笔记, 手写检测程序
    [ ] 如果写不出来, 回炉复习薄弱环节

  4.8 每日 checklist 模板

    你可以把下面这个模板复制到每天笔记的开头:

    ---
    日期: 2026-07-XX
    状态: [ ] 学习中 / [ ] 已掌握
    ---
    [ ] 晨间: git pull + 看计划
    [ ] 学习: noters/dayXX.md
    [ ] 练习: x 题 (手写)
    [ ] 调试: 成功/失败
    [ ] 复习: R1( ) R3( ) R7( ) R14( )
    [ ] 收尾: git push
