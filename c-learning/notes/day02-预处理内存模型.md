# Day02 - C语言基础(下)：预处理、内存模型、输入输出深入

## 形参与实参

  - 形参: 函数定义位置的占位变量
  - 实参: 函数调用时实际传入的值
  - 函数传参是值传递 (拷贝一份给形参)

## 预处理

### 预处理步骤 .c/.h -> .i
  - 执行预处理指令: #include, #define, 条件编译
  - VS中查看预处理文件: 项目属性 -> C/C++ -> 预处理器 -> 预处理到文件 (/P)

### 宏定义 #define

  #define PI 3.14f             // 宏常量
  #define SQUARE(x) ((x)*(x))  // 宏函数 (注意括号)

  - 宏是纯文本替换, 无优先级, 需要用 () 保证运算顺序
  - 全大写 + 下划线命名规范: MAX_SIZE
  - 宏函数 vs 函数: 宏无函数调用开销, 但多次使用增加代码体积

### MSVC 安全警告

  #define _CRT_SECURE_NO_WARNINGS  // 写在 #include 之前
  #include <stdio.h>

  - scanf_s 是微软特有, 不跨平台, 不推荐

## C 程序执行过程

  .c -> .i (预处理)  -> .s (编译)  -> .o (汇编)  -> 可执行文件 (链接)

### 广义编译

  1. 预处理: .c/.h -> .i
     - 展开 #include, #define, 删除注释
  2. 编译(狭义): .i -> .s
     - 词法分析, 语法分析, 类型检查, 生成汇编
  3. 汇编: .s -> .o
     - 汇编器将汇编转成机器码 (二进制目标文件)

### 链接: .o -> 可执行文件

  - 链接器将多个 .o 和库文件整合
  - 链接错误原因: 找不到函数定义
    - 函数名拼写错误
    - 未引用对应头文件
    - 未链接对应的 .o / 库文件

### 编译错误 vs 链接错误

  - 编译错误: 语法问题 (检查语法)
  - 链接错误: 找不到函数体 (C**** 链接错误提示)

## printf 输出缓冲区

  - 全缓冲:  满缓冲刷新 (文件输出)
  - 行缓冲:  遇到 \n 或满 (stdout)
  - 无缓冲:  立即输出 (stderr)

  ️ 建议: printf 末尾加 \n, 确保立即输出
  ️ 程序结束时缓冲区自动刷新

## 虚拟内存

### 概念
  - 虚拟内存是从 0 到最大值的连续地址空间
  - 程序看到的是虚拟地址, OS 映射到物理内存

### 为什么用虚拟内存
  1. 进程隔离: 每个进程独立的地址空间
  2. 避免内存碎片化
  3. 简化程序员的内存管理

### 五大区域

  代码段 (Code)     程序指令, 只读
  数据段 (Data)     全局变量, 静态变量
  堆空间 (Heap)     动态分配 (malloc/free)
  栈空间 (Stack)    局部变量, 函数调用
  内核区域 (Kernel) 操作系统内核

## 字节序

  - 大端: 数据高位存低地址 (高-低, 大-小)
  - 小端: 数据高位存高地址 (高-高, 小-小)
  - x86 架构使用小端
  - 小端优点: 类型转换/指针强转方便, 效率高

  示例: int x = 0x12345678
    小端内存: 78 56 34 12  (低地址->低字节)
    大端内存: 12 34 56 78  (低地址->高字节)

## 冯诺依曼体系

  CPU -> 寄存器 (最快) -> 缓存 (L1/L2/L3) -> 内存 -> 磁盘 (最慢)
  缓存命中: 请求数据已在缓存中, 直接复用, 速度极快

## 调试技巧 (来自课程)

### VS 调试基本操作

  F9       打断点/取消断点
  F5       启动调试 / 跳到下一个断点
  F10      逐过程 (碰到函数会进函数)
  F11      逐语句 (碰到函数跳过, 直接执行完)
  监视窗口 查看变量值变化
  调用堆栈 查看函数调用关系

### 确定断点位置

  - 眼睛扫一下, 哪里容易出错, 就往哪里打断点
  - 别人都说没问题的地方, 大概率没问题

### 程序崩溃排查

  1. 注释法: 注释一段代码, 不崩溃了 => 问题在这里
  2. 根据数据流向分析: 数据从哪来, 被谁改过

### 调试的本质

  - 调试就是信息比对: 实际结果 和 预期结果 比对
  - 程序员心里要有预期

## 代码示例

  #define _CRT_SECURE_NO_WARNINGS
  #include <stdio.h>

  // 宏函数示例
  #define MAX(a, b) ((a) > (b) ? (a) : (b))
  #define MIN(a, b) ((a) < (b) ? (a) : (b))

  int main(void) {
      int x = 10, y = 20;
      printf("MAX(%d, %d) = %d\n", x, y, MAX(x, y));

      // 查看虚拟地址
      int a = 100;
      static int b = 200;
      printf("栈变量 a 地址: %p\n", &a);
      printf("静态变量 b 地址: %p\n", &b);
      printf("main 函数地址: %p\n", main);
      return 0;
  }

## 常见错误 / 盲点

  1. 宏不加括号:
     #define SQUARE(x) x*x
     SQUARE(1+2) => 1+2*1+2 = 5  (不是 9)
  2. scanf 缓冲区问题:
     输入后残留的换行符影响后续 %c
  3. printf 不加 \n:
     可能导致输出未及时显示

## 面试常问

  Q: 讲讲 virtual memory (虚拟内存)?
  A: 先大后小 -- 先说整体概念, 再答细节。
     虚拟内存是一个虚拟的连续地址空间, 从0开始。
     好处: 进程隔离, 避免碎片, 简化管理。
     五大区域: 代码段/数据段/堆/栈/内核。

  Q: 什么是大端和小端?
  A: 数据在内存中的字节排列顺序。
     小端: 低位字节存低地址 (x86架构)
     大端: 高位字节存低地址 (网络协议)
