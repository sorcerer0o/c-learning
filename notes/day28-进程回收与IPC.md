# Day28 - 进程等待与进程间通信 (IPC)

## wait: 等待子进程

- **wait 是一个阻塞函数**, 阻塞结束条件: **等来一个子进程结束** (回收)
- 作用: 父进程等待子进程终止, 并回收子进程的资源 (PCB)

```c
#include <sys/wait.h>
pid_t wait(int *status);
```
- 返回值: 结束的子进程的 PID; 出错 (无子进程) 返回 -1
- status: 出参, 存子进程退出状态 (可传 NULL 不关心)
- 阻塞: 有子进程但都未结束 → 阻塞等待

## 为什么要 wait (僵尸进程)

- 子进程退出后, 如果父进程不及时回收:
  - 子进程虽已退出, 但 PCB (task_struct) 仍残留在内核, 占资源
  - 这种状态叫 **僵尸进程 (Zombie)**
- **wait 的作用就是收尸**: 拿回子进程退出状态, 让内核释放 PCB
- 如果父进程先退出, 子进程会被 init (PID 1) 收养

### 孤儿进程
- 父进程退出而子进程还活着 → 子进程变**孤儿进程**
- 孤儿进程会被 init 收养, 由 init 负责回收

### 僵尸 vs 孤儿
| | 僵尸进程 | 孤儿进程 |
|---|---|---|
| 谁的错 | 父进程没 wait, 子进程先退 | 父进程先退 |
| 状态 | 子进程已死但 PCB 未回收 | 子进程活着, 父进程死了 |
| 危害 | 占 PID/PCB, 需 wait 回收 | 无害, 被 init 收养 |

## waitpid: 等指定子进程

```c
#include <sys/wait.h>
pid_t waitpid(pid_t pid, int *status, int options);
```
- 与 wait 的区别: 可以指定等待**哪个**子进程
- pid > 0: 等指定 pid 的子进程; pid = -1: 等任意子进程 (类似 wait)
- 非阻塞方式: options 传 WNOHANG → 没有子进程结束则立即返回 0, 不阻塞

## 管道补充: 匿名管道 vs 有名管道

- 进程间的通信方式:
  - **匿名管道 (pipe)**: 无名字, **只能用于有血缘关系 (父子/兄弟) 进程间通信**
  - **有名管道 (FIFO)**: 在文件系统中有路径名, 无血缘关系进程也能通信

### pipe 函数 (匿名管道)
```c
#include <unistd.h>
int pipe(int pipefd[2]);
```
- pipe 创建的匿名管道**只能用于有血缘关系的进程间通信** (fork 继承)
- `pipefd[0]`: 读端; `pipefd[1]`: 写端
- 常见用法: fork 后父进程关读端、子进程关写端 (或反之), 形成单向数据流

### 有名管道 (FIFO)
- 通过 `mkfifo` / `mkfifo(3)` 创建, 以文件形式存在于文件系统 (类型 p)
- 打开方式类似普通文件 (open), 但本质是内核缓冲区
- 无亲缘关系的两个进程也可通信: 一个 open 读端, 一个 open 写端

## IPC 总览: 进程间通信

- 进程内存隔离 → 数据不能直接共享, 需要 IPC
- 常见 IPC 方式:

| 方式 | 特点 | 适用场景 |
|---|---|---|
| 管道 (pipe) | 内核缓冲区, 半双工, 父子进程 | 简单数据流传 |
| 有名管道 (FIFO) | 通过文件系统路径, 无亲缘进程也能通 | 不同进程间流式数据 |
| 信号 (signal) | 异步通知事件 | 简单事件通知 |
| 共享内存 / mmap | 直接共享一段内存, 最快 | 大数据量共享 |
| 消息队列 | 内核维护的消息链表 | 结构化消息 |
| 套接字 (socket) | 网络/本机通用 | 跨机器或通用通信 |

## 守护进程

- **守护进程 (Daemon)**: 脱离终端、后台常驻运行的特殊进程
- 特点:
  - 后台运行, **没有控制终端** (不受终端关闭/登录退出影响)
  - 常驻系统, 生命周期与系统基本一致
  - 名字通常以 **d 结尾** (如 sshd, httpd, crond, mysqld)
- 创建守护进程的核心: 脱离会话/进程组 (setsid), 改变工作目录, 重定向标准流到 /dev/null

## 日志的相关概念

- 日志: 记录程序运行状态/错误/关键事件的信息, 便于排查问题
- 相关概念:
  - **日志级别**: 从低到高 (DEBUG < INFO < WARNING < ERROR < FATAL), 记录时过滤
  - **日志文件**: 系统日志一般在 `/var/log/` (如 syslog, messages)
  - **syslog**: Linux 标准的日志记录机制, `syslog(3)` 函数/`logger` 命令写日志
- 程序日志的作用: 故障定位、运行监控、安全审计

## 信号 (signal)

### 信号是什么
- **信号是一种异步的事件通知机制, 也是一种进程间通信机制**
- 进程收到信号后, 可以忽略/捕获处理/按默认行为处理

### 中断与信号的区别 (重点)
| | 中断 | 信号 |
|---|---|---|
| 针对对象 | **CPU** | **进程** |
| 执行时机 | 产生后**立刻执行** | 产生后**可能有延迟** (进程调用时机) |
| 未处理时的存储 | 硬件直接处理 | 可能存储在进程的**未决信号集**里 |

- 未决信号集 (pending set): 信号已产生但进程还没处理, 信号会暂存在进程的未决信号集中

### 硬件中断 / 软件中断
- 硬件中断: 硬件设备通知 CPU 需要处理事件 (如键盘输入、时钟)
- 软件中断: 软件程序通知 CPU 需要处理事件 (如系统调用就是典型的软件中断)

### 信号来源
1. 用户交互 (如 Ctrl+C 产生 SIGINT)
2. 错误或异常条件 (如 除零、段错误)
4. 系统状态变化 (如子进程终止 SIGCHLD、定时器超时 SIGALRM)
5. 显式的信号发送 (`kill` 命令 / `kill()` 函数)

### 常见信号
| 信号 | 值 | 产生 | 默认行为 |
|---|---|---|---|
| SIGINT | 2 | Ctrl+C | 终止进程 |
| SIGQUIT | 3 | Ctrl+\ | 终止并产生 core dump |
| SIGKILL | 9 | kill -9 | 立即终止 (不可捕获/忽略) |
| SIGSTOP | 19 | Ctrl+Z | 停止进程 (不可捕获/忽略) |
| SIGCONT | 18 | kill -CONT | 继续之前被停止的进程 |
| SIGTERM | 15 | kill 默认 | 终止进程 (可捕获: 优雅退出) |
| SIGCHLD | 17 | 子进程退出 | 忽略 / 通知父进程 |

- 补充: `kill -l` 查看所有信号; SIGKILL/SIGSTOP 两个信号不能被捕获或忽略

## 常用进程命令参考

- `ps -elf` / `ps aux` 查进程
- `top` 看负载 (load average 1/10/15 分钟)
- `kill -2` / `kill -9` 发信号
- 查看僵尸进程: ps 输出中 STAT 列 Z
