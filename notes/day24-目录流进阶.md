# Day24 - 目录流进阶: 复习巩固与文件信息获取

## 复习: 三类函数与选择原则

### 系统调用 / ISO-C / POSIX 的关系
- **系统调用**: 内核对外暴露功能的一种方式. Linux 内核是 C 写的, 所以系统调用以 C 函数形式暴露
- **ISO-C**: 任何 C 语言平台都会遵循的规则, 定义了跨平台一致的库函数
- **POSIX**: 类 Unix 平台下, 有约束力的 C 函数标准
- **ISO-C、POSIX 可能是系统调用的"套壳"**: 其本质底层可能就是系统调用 (如 fopen 底层就是 open)

### 选择原则
- 同一功能三者都有 → **优先选择 ISO-C** (跨平台性最好)
- 根据使用范围选择: **ISO-C > POSIX > 系统调用**
- 如果追求效率 (且不考虑可移植性) → 可直接用系统调用 (少一层封装, 更快)

## 复习: 结构体指针

- 结构体指针作为参数传递: 用解引用 `(*p).xxx`, 但更直观的是用**箭头运算符 `->`**
- `p->xxx` 等价于 `(*p).xxx`

```c
struct stat sb;
stat("a.txt", &sb);
printf("%lu", sb.st_size);    // 结构体变量用 .
printf("%lu", statbuf->st_size);  // 结构体指针用 ->
```

## 复习: 位运算判断权限

- 使用位运算 `&` 判断对应位置权限是否存在: 若对应位同为 1 则返回 1, 否则返回 0
- 例: `mode & 0400` 判断所有者是否有读权限 (0400 = 400 八进制)

## 复习: switch 判断文件类型

- 使用 `switch` 判断文件类型: `switch (st_mode & S_IFMT)` 与各 `S_IFxx` 宏比较
- 系统工具 `ls -la` 第一列首字符 (d/-/l...) 就是文件类型

## 复习: 时间戳转换

- 引用函数 `localtime(&timestamp)` 把时间戳转换为 struct tm, 再取年月日时分秒字段格式化输出

## 学习: 目录流

### 什么是目录流
- 目录流是符合 **POSIX 标准的 C 语言库函数**, 只能在类 Unix 平台使用 (Windows 不可直接用)
- 目录流的作用: **读取目录中的内容** (列出目录下有哪些文件/子目录)
- 目录中存储的是各文件/子目录的**目录项 (dirent)**, 通过目录流可一条条读出来
- 类比已有知识: 目录流指针类似文件流 FILE 指针, 指向目录文件的读写位置

### 读目录流
- `opendir(dirpath)` 打开目录流 → 返回 `DIR*`
- `readdir(dirp)` 依次读取目录项, 返回 `struct dirent*`, 读完返回 NULL
- `closedir(dirp)` 关闭目录流释放资源

### dirent 结构体 (关键字段)
```c
struct dirent {
    ino_t          d_ino;       // inode 编号
    off_t          d_off;       // 到下一个目录项的偏移量
    unsigned short d_reclen;    // 目录项大小
    unsigned char  d_type;      // 文件类型 (DT_REG 普通文件 / DT_DIR 目录 / ...)
    char           d_name[256]; // 文件名
};
```
- 通过 `d_name` 拿到文件名, 通过 `d_type` 判文件类型 (是目录还是普通文件等)

## 学习: 指针要点

### 指针的关键
- 指针的关键不是指针本身, 而是**指针指向的内存**
- 使用指针前要**保证指针指向的内存大小够用** (如 buf 数组开得够大)
- 例: readdir 返回的 dirent 是系统静态分配的 (够 256 文件名), 不自己分配

### 永远不要返回当前栈区的指针
- **栈区指针在函数调用结束后, 生命周期就结束了** → 返回的指针将悬空, 访问是未定义行为
- 解决: 申请**堆区指针** (malloc) 再返回, 由调用者负责 free
```c
// 错误示例
int *func(void) {
    int x = 10;
    return &x;   // x 生命周期结束, 指针悬空
}

// 正确示例
int *func(void) {
    int *p = malloc(sizeof(int));
    *p = 10;
    return p;    // 堆区, 调用者记得 free
}
```

## 学习: stat 系统调用 (获取文件详细信息)

### 为什么需要 stat
- 目录项 (dirent) 只有文件名、类型等少量信息, 拿不到文件大小、权限、时间等
- 目录流解决"有哪些文件", **stat 解决"文件细节信息"**

### 理解 stat 能获什么
- 建议使用 `ls -la` 来判断 stat 所能获取的信息:
- **`ls -la` 显示的信息, 除了"名称", stat 全部都有** (权限/链接数/属主/组/大小/时间)
- **stat 不能返回名称** — 名称目前可以用目录流的 `d_name` 实现 (组合使用即可还原 ls -la)

### stat 的结构体核心字段
```c
struct stat {
    mode_t   st_mode;   // 文件类型 + 权限
    nlink_t  st_nlink;  // 硬链接数
    uid_t    st_uid;    // 属主 ID
    gid_t    st_gid;    // 属组 ID
    off_t    st_size;   // 文件大小 (字节)
    /* st_mtime 最后修改时间 */
};
```
- 权限/类型在 st_mode, 通过 `&` 与 `switch` (上文复习) 提取
- 属主/属组 ID 可用 `getpwuid` / `getgrgid` 转成用户名/组名
- 时间戳用 `localtime` 转成日期格式

## 学习: 缓冲区

### 有无缓冲区的概念
- 有/无缓冲区, 指的是**有无用户态缓冲区**
- 有缓冲: C 标准库 FILE 流 (fopen/fread/fwrite) — 在用户内存区预留一块缓冲
- 无缓冲: 直接系统调用 (open/read/write) — 用户进程直接和内核态缓冲区交互

### 缓冲区的作用
- 减少**从内核区域获取数据**时, 用户态↔内核态**来回切换的次数** → 提高效率
- 因为切换过程效率低下 (系统调用远比普通函数调用代价昂贵: 状态切换 + 内存复制)

### 为什么切换效率低下
- 系统调用过程: 用户态 → 内核态 → 执行操作 → 回归用户态
- 每次切换都要保存/恢复上下文, 代价高
- 用户态缓冲区一次多读/多写"一大块", 减少系统调用次数, 从而减少切换次数

## 学习: 查看类型别名/结构体具体定义

- 涉及: `mode_t` `off_t` `pid_t` `uid_t` 等类型别名、struct 内部的字段
- 步骤:
```bash
gcc -E test1.c -o test1.i        # 生成预处理文件 (test1.c 需包含对应头文件)

```
