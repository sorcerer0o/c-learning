# Day26 - 管道与 IO 多路复用 (select)

## 复习: 阻塞队列

- 阻塞队列: **大小有限的队列**
- 两种阻塞:
  - **读空阻塞**: 队列无数据时 read 会阻塞等待
  - **写满阻塞**: 队列满时 write 会阻塞等待
- 前提: 读空/写满阻塞要求队列的读端和写端**都存在** (否则单端阻塞无意义或直接关闭)

### 复习: 动态队列的实现
- 用数组 + 首尾下标 (head/tail) 实现循环队列
- 队列扩容的思考: **为什么不能用 realloc**
  - 队列元素可能"环绕"在数组两端, 不是连续内存 → realloc 会把整块搬走或失败
  - 循环队列扩容需要: 申请新数组 → 按逻辑顺序拷贝 → 释放旧数组
  - 直接 realloc 破坏循环结构的连续性/顺序正确性

### 阻塞队列的应用
- 生产者消费者模型的数据中转
- 解耦生产与消费速度

## 管道 (pipe)

### 管道是什么
- **管道用于两个进程之间进行通信** (进程间通信 IPC 的一种)
- 本质: 内核维护的一块缓冲区 (像队列), 一端写一端读
- 管道是**半双工**的: 数据只能单向流动
  - 全双工: 同一时刻双向收发
  - 半双工: 同一时刻只能一个方向 (可切换)
  - 单工: 方向固定
  - 一般情况下管道都是**以单工方式使用**: 一端固定写, 一端固定读

### 管道的基本使用
- 使用两个程序: 一个程序开读端, 一个程序开写端, 用管道把写端数据传到读端

```c
#include <unistd.h>
int pipe(int pipefd[2]);
```
- `pipefd[0]` 读端, `pipefd[1]` 写端
- 成功返回 0, 失败返回 -1

### 管道的行为特性
- **只开读端或只开写端会阻塞** (另一端不存在时无法进行)
- read 比 write 快: 管道中没数据 → **read 阻塞** (等数据)
- write 比 read 快: 管道满 → **write 阻塞** (等空位)
- 关闭一端会发生什么:
  - **读端关, 写端继续写**: 写端收到退出信号 (SIGPIPE), 进程退出
  - **写端关, 读端继续读**: 读端可以把剩余数据读完, 然后 read 返回 0 (EOF), 不会阻塞

### 读写顺序注意
- 要**先写后读**: read 读空会立刻阻塞; 写满阻塞需要积累一段时间
- 所以生产端先写, 消费端后读, 避免一上来就阻塞

### 数据模型
- 使用**两个管道**实现双向 (双工) 数据传输模型:
  - 管道 1: 进程 A 写 → 进程 B 读
  - 管道 2: 进程 B 写 → 进程 A 读
- fork 后子进程继承管道 fd; 父进程关读端, 子进程关写端, 形成单向链路

## IO 多路复用: select

### 为什么需要 select
- 多个 fd 都要读, 不知道哪个先来数据
- 循环 read 会造成**阻塞** (等某个 fd 数据时错过其他 fd)
- select 可以**同时监听多个 fd**, 一旦有可用 fd 就返回

### select 函数
```c
#include <sys/select.h>
int select(int nfds, fd_set *readfds, fd_set *writefds, fd_set *exceptfds, struct timeval *timeout);
```
- 作用: 监听文件描述符是否可用 (可读/可写/异常)
- 返回值: **可用的文件描述符数量**; 超时返回 0; 出错返回 -1
- 是阻塞函数: 有可用 fd 就返回, 否则一直阻塞 (无 timeout) 或等到 timeout

### 参数解释
- **readfds**: 要监听"可读"的 fd 集合
- **writefds**: 要监听"可写"的 fd 集合
- **exceptfds**: 异常集合 (一般不用)
- **timeout** (struct timeval): 最长等待时间 (可设置超时), 也可以 NULL 无限等待
- **nfds**: 所有 fd 中的最大值 + 1, 用作内核**轮询访问文件对象**的范围上限

### fd_set 的本质
- **fd_set 是个位图 (bitmap)**: 用二进制的某一位为 1, 来表示监听/使用的文件描述符
- 例: 位图第 3 位为 1 → 表示文件描述符 3 在集合中
- fd_set 操作函数 (宏): `FD_ZERO` 清空 / `FD_SET` 添加 / `FD_CLR` 移除 / `FD_ISSET` 判断

### select 流程
1. 声明 fd_set 并用 `FD_ZERO` 清零
2. 用 `FD_SET` 把要监听的 fd 加入 readfds
3. 记录 nfds = 最大 fd + 1
4. (可选) 设置 timeout
5. 调用 select (阻塞)
6. **select 返回后, 用 FD_ISSET 遍历检查: 还留在 readfds 中的 fd, 就是可用的 fd**
7. 对可用的 fd 执行 read/write, 处理完再回到第 2 步重新设置集合 (select 会修改集合)

### select 的典型代码模板
```c
int main(void) {
    fd_set rfds;
    int max_fd = 0;
    while (1) {
        FD_ZERO(&rfds);
        FD_SET(fd1, &rfds);          // 加入所有要监听的 fd
        FD_SET(fd2, &rfds);
        max_fd = (fd1 > fd2 ? fd1 : fd2) + 1;

        int n = select(max_fd, &rfds, NULL, NULL, NULL);  // 阻塞等待
        ERROR_CHECK(n, -1, "select");

        if (FD_ISSET(fd1, &rfds)) { ... read(fd1) ... }   // fd1 有数据可读
        if (FD_ISSET(fd2, &rfds)) { ... read(fd2) ... }
    }
}
```
