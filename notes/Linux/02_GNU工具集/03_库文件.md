# 概述

> _~Gn!~_
>
> 在C语言开发过程中，我们常会在源代码中调用一些外部函数，比如printf函数等。
>
> 这个源文件编译后会得到`.o`目标文件，此时该文件中只有这些外部函数的标识符，但这些标识符尚未映射到具体的函数入口地址。所以`.o`文件尽管包含了程序的结构，但还不是一个可执行文件，不可以独立执行。
>
> 于是接下来进行的链接阶段，链接器会将多个`.o`文件以及<font color=red>**库文件**</font>等相关文件，全部链接在一起。如果链接成功，外部函数的标识符就会链接到一个正确的函数入口地址，最终生成一个完整的可执行文件。
>
> `.o`文件我们很熟悉了，那么什么是库文件呢？这一小节，我们就来回答这个问题。
>
> 简单粗俗的理解：
>
> 库文件就是一堆已经写好的、很成熟好用的代码组成的目标文件集合。库文件主要用于提供常用的程序功能，如数学运算、字符串处理、文件操作等，以避免开发者重复编写这些功能的代码。
>
> 在业界会把库文件叫做"轮子"，我们要避免重复造"轮子"，当一个实现已经在库文件中已经存在很好的实现时，往往就没有必要自己写了。
>
> <font color=red>**从本质上来说：库文件是一种可执行代码的二进制形式，可以被操作系统载入内存执行 (说得更通俗易懂点，就是目标文件的集合)。**</font>
>
> 注：
>
> 这一节的目的是让大家学会创建与使用静态库、动态库，知道静态库与动态库的区别，知道使用的时候如何选择。更深入的知识就不必了解了。

# 库文件的分类

> _~Gn!~_
>
> 库文件可以分为两大类：
>
> 1. 静态库文件
> 2. 动态库文件
>
> 静态库文件：
>
> 1. 静态库，通常以 `.a`（在Unix、Linux系统中）或 `.lib`（在Windows系统中）为文件扩展名。
> 2. <span style=color:red;background:yellow>**所谓静态库是指：在链接的过程中，静态库的内容会直接整体合并到最终的可执行程序中。**</span>
> 3. <span style=color:red;background:yellow>**静态库对函数的链接是在链接阶段完成的，在程序运行时，程序和静态库没有半点瓜葛。**</span>
>
> 动态库文件：
>
> 1. 动态库，通常以 `.so`（在Unix、Linux系统中）、`.dll`（在Windows系统中）为文件扩展名。
> 2. <span style=color:red;background:yellow>**所谓动态库是指：动态库的内容在程序运行时才被载入内存中。**</span>
> 3. <span style=color:red;background:yellow>**动态库对函数的链接是在运行时完成的，链接过程不处理动态库。**</span>
>
> > **生动理解动态库和静态库**
> >
> > 首先把库理解成轮子，静态库和动态库的区别，就类似于家用汽车轮子和F1赛车轮子：
> >
> > ![动态库和静态库-图](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403031427490.png#padding#400w)
> >
> > 静态库、家用汽车轮子：家用车的轮子是直接在组装时，就装上去的，是独立的不受影响的轮子。
> >
> > 动态库、F1赛车的轮子：需要在比赛时，根据不同的路况天气选择不同的轮胎，是后装上去的轮子。
>
> 在以前的课程中，我们反复讲过在链接的过程中，链接器会自动去到系统库文件目录下链接系统的库文件，比如像`printf`函数这样的标准库函数的链接。
>
> 在Linux环境下，C标准库文件的一般会命名为：
>
> 1. **`libc.a`**：C语言标准静态库文件
> 2. **`libc.so`**：C语言标准动态库文件
>
> 它们一般会放在`/usr/lib`目录下，你可以使用指令：
>
> ```` shell
> find /usr/lib -name "libc.a" -or -name "libc.so"		# 直接采用文件名来查询目标文件
> ````
>
> 来寻找它们。

## 优缺点

> _~Gn!~_
>
> <font color=red>**使用静态库的优点是：**</font>
>
> 1. 最终的可执行文件包含了所有必需的内容，因此不需要额外的库文件就可以直接运行。
> 2. 这样的可执行程序移植起来非常方便，因为你无法确保目标机器就必然拥有相应的库。
>
> <font color=red>**使用静态库的缺点是：**</font>
>
> 1. 直接包含库文件会导致最终可执行程序很大，浪费内存空间。
> 2. 库文件如果更新，往往需要重新生成可执行程序，对开发者和使用者都不友好。(开发者需要重新发布版本、使用者需要重新下载)
>
> <span style=color:red;background:yellow>**使用动态库的优势是：**</span>
>
> 1. 减少可执行程序的最终大小
> 2. 多个可执行程序完全可以共用同一个动态库，可以减少了内存占用
> 3. 库文件和可执行程序独立解耦，更新库文件后，一般不需要重新生成可执行程序，这对开发者和使用者都很友好。
>
> <span style=color:red;background:yellow>**使用动态库的缺点是：**</span>
>
> 1. 缺少动态库则程序完全无法执行，移植性差。(在Windows中，大家肯定都碰到过缺少`xx.dll`文件无法运行的情况)
> 2. 运行时链接，会耗费一定的运行时性能。（游戏加载时，往往需要加载动态库，影响游戏加载速度）
>
> 当我们正常使用`gcc`指令生成一个可执行程序时，默认会链接一部分动态库，这样能够有效减少生成可执行文件的大小。
>
> 而我们也可以使用指令：
>
> ```` shell
> gcc main.c -o main_static -static
> ````
>
> 这样就会得到一个更大的多的可执行程序。（可以通过`nm`查看符号链接表对比）

## 如何选择？

> _~Gn!~_
>
> 在Linux下，当我们使用`gcc`编译链接生成可执行程序时，默认会选择动态库链接以减少可执行程序的大小。你可以在链接时加上选项`-staic`使用静态库链接，你会发现生成的可执行程序会大非常多。
>
> 那么在实际应用中，我们该选择静态库链接还是动态库呢？
>
> 当你了解了静态和动态库的区别，以及它们的优缺点后，这个问题实际上并不难回答。 选择静态库还是动态库主要取决于你的具体需求和应用场景。比如：
>
> 1. 从部署难度和独立性考虑：
>    1. 如果你希望你的应用程序是完全独立的，不依赖于外部库文件，或者你需要确保应用总是运行特定版本的库，那么选择静态库可能更合适。
>    2. 如果你希望多环境部署和使用应用程序，那么还是选择静态库更安全稳定一些。
> 2. 从程序大小和内存使用考虑：
>    1. 如果你希望最小化应用程序的大小，并且当多个程序可能同时运行并共享相同的库时减少内存占用，动态库是一个更好的选择。
>    2. 比如一个大型游戏就可以依赖一些动态库，来减少自身体积以及运行时的内存占用。
> 3. 从性能考虑：
>    1. 如果应用程序的启动时间非常关键，并且你想避免动态加载库带来的任何潜在延迟，静态链接可能是更好的选择。
>    2. 如果运行时性能比初始加载时间更重要，并且你的应用可以承受初次加载动态库的额外时间，那么动态库可以是一个合适的选择。
>    3. 比如游戏，第一次打开游戏或者加载新地图资源等，往往都会比较慢，就是因为选择链接了动态库。
> 4. 从移植稳定性考虑：
>    1. 使用静态库的稳定可用性必然会更强，如果希望程序总是能够稳定运行，可以考虑静态库
>    2. 如果不考虑稳定性，而是更愿意实时接收更新内容，那么使用动态库是更优的选择。
>
> 到了公司里，具体选择静态库还是动态库，要看公司的具体选择。我们作为普通的开发者，会用即可。

# 生成静态库

> _~Gn!~_
>
> 下面我们讲一下如何来手动生成一个静态库。
>
> 假如我们写了一个很好用的算法库，里面包含了加、减法(笑)，如下所示：
>
> 首先创建一个头文件<span style=color:red;background:yellow>**my_compute.h**</span>，内容如下：
>
> ```c
> // my_compute.h
> #ifndef __WD_MY_COMPUTE_H
> #define __WD_MY_COMPUTE_H     
> 
> int add(int a, int b);	// 加
> int sub(int a, int b);	// 减
> 
> #endif
> ```
>
> 然后新建两个.c文件，分别对应这两种运算规则的实现，代码如下：
>
> ```c
> // add.c
> #include "my_compute.h"
> #include <stdio.h>
> 
> int add(int a, int b) {
>     return a + b;
> }
> 
> // sub.c
> #include <stdio.h>
> #include "my_compute.h"
> 
> int sub(int a, int b) {
>     return a - b;
> }
> ```
>
> 然后编写一个`main.c`文件，代码如下：
>
> ```` c
> #include <stdio.h>
> #include "my_compute.h"
> 
> int main(void){
>     printf("1 + 1 = %d\n", add(1, 1));
>     printf("2 - 2 = %d\n", sub(2, 2));   
>     return 0;
> }
> ````
>
> 直接使用指令生成可执行文件：
>
> ```` shell
> gcc main.c -o main -Wall -g
> ````
>
> 肯定会失败，而且是因为链接失败，因为无法找到add等函数的定义代码完成链接操作。此时你可以执行下面的操作：
>
> ```` shell
> gcc -c add.c -o add.o				# 生成add.o目标文件
> gcc -c sub.c -o sub.o				# 生成sub.o目标文件
> gcc main.c add.o sub.o -o main		# 指示gcc链接外部目标文件合并生成可执行程序
> ````
>
> 如果想要更方便一些，可以将`add.o`和`subtract.o`直接合并打包成一个静态库，指令如下：
>
> ```` shell
> ar crsv my_compute.a add.o sub.o 	#静态库一般以.a结尾, 库的名字为my_compute
> ````
>
> 关于这个指令，具体的解释如下：
>
> 1. `ar`：`ar` 命令指是执行静态库相关操作的起始命令。
> 2. `crsv`：这是 `ar` 命令的选项，具体含义如下：
>    1. `c`：表示创建一个新的静态库文件。如果该库已经存在，则将其重新创建。
>    2. `r`：表示将指定的目标文件添加到静态库中，或者用新的目标文件替换现有的同名目标文件。
>    3. `s`：表示创建一个包含索引（symbol table）的静态库文件，这样可以提高链接速度。
>    4. `v`：表示在执行命令时显示详细信息，通常用于输出详细的操作信息。
> 3. `my_compute.a`：这是要创建的静态库文件的名称。在这里，静态库文件名为 `my_compute.a`。
> 4. `add.o` 和 `subtract.o`：这是要添加到静态库中的目标文件。
>
> 综上所述，这个指令的作用是创建一个名为 `my_compute.a` 的静态库文件，并将 `add.o` 和 `subtract.o` 这两个目标文件添加到这个静态库中。
>
> 得到这个静态库文件后，就可以使用以下指令来链接生成可执行程序了：
>
> ```` shell
> gcc main.c my_compute.a -o main
> ````
>
> 从这里，就可以看出：<font color=red>**静态库文件实际上就是目标文件的合集。**</font>
>
> 当然你还可以更进一步，把将生成的静态库移动(或复制)到`/usr/lib`目录下，这个目录是Linux操作系统的库文件目录，操作需要sudo权限：
>
> ```` shell
> sudo mv my_compute.a /usr/lib/libmy_compute.a		#注意lib目录下的库文件应该以lib开头
> ````
>
> <span style=color:red;background:yellow>**注意：将库文件放入上述库文件目录时，命名一定要以"lib"开头！这样的命名才能够使用"-l"选项在链接时链接这个库文件！**</span>
>
> 执行这样的操作后，你就可以执行以下指令来生成可执行程序了：
>
> ```` shell
> gcc main.c -o main -lmy_compute		#放入库文件目录的库文件命名一定要以"lib"开头，否则会找不到
> ````
>
> 上面的指令表示在链接的过程中，去`/usr/lib`目录中寻找名为**"libmy_compute.a"**的库文件！
>
> 最后思考两个问题：
>
> 1. 假如执删除了`/usr/lib`目录下的该静态库文件，会影响到原本已生成的程序的执行吗？
>
>    答：自然是不会的，旧的静态库文件已经链接到程序本体中了，不重新生成可执行程序的情况下，可执行程序不会改变实现。
>
> 2. 如果重新打包一份修改了内容的、但命名不变的静态库文件<font color=red>**覆盖到**</font>`/usr/lib`目录下，原先已生成的可执行程序会改变执行结果吗？
>
>    答：也是不会的，程序需要重新编译链接才会更新静态库的内容。

# 生成动态库

> _~Gn!~_
>
> 上面你已经学会生成静态库文件并使用了，那么下面一起来看一看动态库文件的生成。
>
> 首先，动态库文件生成的第一步就稍有区别，生成目标文件时要加上`-fpic`选项：
>
> ```` shell
> gcc -c add.c -o add.o -fpic			# -fpic选项必须加上
> gcc -c sub.c -o sub.o -fpic			# -fpic选项必须加上
> ````
>
> 这个`-fpic`选项是什么意思呢？
>
> 官方点的说法是：生成位置无关的机器语言代码目标文件。
>
> 通俗点说：
>
> 1. 动态库又叫做共享库，多个可执行程序将动态库加载到内存使用时，肯定需要会加载到内存的不同位置。
> 2. 不加该选项时，生成的目标文件机器指令代码都有一个绝对的地址偏移位置(比如永远在0X.....)
> 3. 但加上该选项绝对位置就变成了相对位置。基于这样的改变，才能够实现多个进程共享同一个库，才是一个共享动态库。
>
> 第二步仍然是将这些目标文件打包，生成一个动态库文件，指令如下：
>
> ```` shell
> gcc -shared add.o sub.o -o libmy_compute.so		#库文件的命名仍然不要忘记以lib开头
> ````
>
> 解释一下这个指令：
>
> 1. `gcc`：静态库生成可以看成目标文件打包，但动态库的生成却涉及复杂的编译和链接过程，需要gcc编译套件参与。
> 2. `-shared`: 这个选项告诉gcc编译器要生成一个共享库，也就是动态库文件，而不是一个可执行程序。
> 3. `-o my_compute.so`: 这部分指定了输出文件的名称。`-o` 选项后面跟着的是输出文件的名字，在Linux系统上，动态库通常有 `.so` 扩展名。
>
> 这个指令的格式和静态库生成稍有区别，需要注意一下。
>
> 生成完动态库以后，下面的操作就和静态库一样了，把动态库文件放入目录`/usr/lib`中。
>
> <span style=color:red;background:yellow>**注意：动态库的运行时链接默认会去系统库目录下寻找，不会去当下工作目录中寻找，所以使用动态库必须放入系统库文件目录中，这一点和静态库文件是不同的。**</span>
>
> 将动态库文件放入后，就可以使用下列指令生成一个使用动态库的可执行程序了：
>
> ```` shell
> gcc main.c -o main -lmy_compute			#放入库文件目录的库文件命名一定要以"lib"开头，否则会找不到
> ````
>
> 我们最后同样思考几个问题：
>
> 1. 如果删除该动态库文件，已生成的可执行程序还能继续执行吗？
>
>    答：当然无法执行，因为可执行程序需要在运行时链接这些动态库文件。
>
> 2. 如果重新打包一份修改内容的动态库文件，已生成的可执行程序还能正常执行吗？行为会发生变化吗？
>
>    答：能正常执行，但行为可能会根据库的更改而变化。如果函数实现发生变化（如修正bug或改变算法），则程序的运行结果或表现可能与之前不同。
>
> 实际上更新动态库，以实现即时更新应用的操作很普遍，为了更方便的管理动态库文件以及方便回退版本等。我们讲解一下公司里会普遍采取的做法：
>
> ```` shell
> gcc -shared add.o sub.o -o libmy_compute.so.0.0.1			#后面的.0.0.1代表动态库的版本号
> sudo mv libmy_compute.so.0.0.1 /usr/lib						#将生成的动态库移动到/usr/lib目录下
> ````
>
> 然后在目录`/usr/lib`下创建一个软链接：
>
> ```` shell
> sudo ln -s libmy_compute.so.0.0.1 libmy_compute.so			#创建符号链接libmy_compute.so，指向最新版本的动态库文件
> ````
>
> 注意：`ln -s`指令的第一个参数是被链接的目标文件，第二个参数才是生成的软链接快捷键方式！！
>
> 这样的话，在外部表链接可执行程序的时候，就都可以使用指令：
>
> ```` shell
> gcc main.c -o main -lmy_compute		#链接生成可执行程序
> ````
>
> 而更新动态库只需要修改软链接的指向：
>
> ```` shell
> sudo ln -sf libmy_compute.so.0.0.2 libmy_compute.so			#软链接指向新版动态库
> ````
>
> 该指令中的两个选项的含义是：
>
> 1. `-s`: 表示创建符号链接。
> 2. `-f`: 如果目标软链接文件已经存在，则强制删除它并创建新的链接文件。
>
> 这样的做法大家可以了解一下，等开始工作后，在公司里就可以多留心一下这样的细节。

> _~Gn!~_
>
> 有同学提到了一个有趣的问题：若生成两个同名的静态库文件和动态库文件，放入`usr/lib`目录下，如下图所示：

> gcc main.c -o main -lmy_compute
> ````
>
> 那么最终链接生成的可执行程序是链接动态库还是静态库呢？
>
> 实际上，当使用GCC进行编译并链接时，如果在系统库文件目录中同时存在同名静态库（`.a`文件）和动态库（`.so`文件），<span style=color:red;background:yellow>**GCC会优先链接到动态库文件**</span>。
>
> 这是因为，链接动态库可以获得更好的灵活性以及可以节省空间。
>
> 当然，你也可以显式指定GCC去链接静态库文件，这样生成的可执行程序体积会更大一些：
>
> ```` shell
> gcc main.c -o main -lmy_compute -static
> ````
>
> 以上。
