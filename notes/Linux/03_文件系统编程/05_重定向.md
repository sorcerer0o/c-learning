# 文件流和文件描述符的关系

> _~Gn!~_
>
> `fopen` 函数实际上在运行的过程中也获取了文件的文件描述符，这一点非常容易验证，我们只需要：
>
> 1. 用`fopen`库函数打开一个文件
> 2. 然后用`write`系统调用函数，使用文件描述符3写文件数据
>
> 代码如下：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>     // 利用fopen打开一个文件
>     FILE *fp = fopen(argv[1], "w+");
>     ERROR_CHECK(fp, NULL, "fopen");
> 
>     // fileno函数用于获取文件流当中的文件描述符
>     write(3, "hello", 5);
>     ERROR_CHECK(ret, -1, "write");
>     close(fp);
>     return 0;
> }
> ````
>
> <font color=red>**这个写操作是可以成功的，hello这个字符串将被写入到文件里。**</font>
>
> 这说明：
>
> 1. fopen的底层就是系统调用函数open，所以它也有文件描述符的概念
> 2. 文件描述符的分配是从3开始的，012则被标准流保留了。
>
> 当然上述代码中直接使用魔法数，还是不太好，我们可以利用`fileno`函数（ISO-C标准C语言库函数）来获取已打开文件流的文件描述符。
>
> 该函数的声明如下：
>
> ```` c
> #include <stdio.h>  // fileno 函数的声明在这个头文件中
> int fileno(FILE *stream);
> ````
>
> <font color=red>**参数需要传入一个已打开的文件流，返回值则是该文件流的文件描述符。**</font>
>
> 这样我们就可以把代码改成下面的样子：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>     FILE *fp = fopen(argv[1], "w+");
>     ERROR_CHECK(fp, NULL, "fopen");
> 
>     // fileno函数用于获取文件流当中的文件描述符
>     write(fileno(fp), "hello", 5);		// 用fileno函数来获取文件描述符，代替魔法数字
>     ERROR_CHECK(ret, -1, "write");
>     close(fp);
>     return 0;
> }
> ````
>
> 好到这里，你已经了解文件流和文件描述符的关系，实际上我们可以更进一步的去了解`FILE`这个结构体。
>
> 你仍然可以通过查看预处理后生成的`.i`文件的方式，来查看`FILE`结构体的定义，使用vim编辑器打开预处理后得到的文件，然后直接输入下列指令回车查找这个结构体：
>
> ````
> /struct.*FILE
> ````
>
> 该结构体的内容大体如下所示：
>
> ````c
> struct _IO_FILE{
>     int _flags;
>     char *_IO_read_ptr;		// 当前读取位置的指针
>     char *_IO_read_end;
>     char *_IO_read_base;
>     char *_IO_write_base;
>     char *_IO_write_ptr;	// 当前写入位置的指针
>     char *_IO_write_end;
>     char *_IO_buf_base;
>     char *_IO_buf_end;
>     char *_IO_save_base;         
>     char *_IO_backup_base;
>     char *_IO_save_end;
>     struct _IO_marker *_markers;
>     struct _IO_FILE *_chain;
>    
>     int _fileno; 	// 文件描述符
>     int _flags2;
>     __off_t _old_offset;
>     unsigned short _cur_column;
>     signed char _vtable_offset;
>     char _shortbuf[1];
>     _IO_lock_t *_lock;
>     __off64_t _offset;
>     struct _IO_codecvt *_codecvt;
>     struct _IO_wide_data *_wide_data;
>     struct _IO_FILE *_freeres_list;
>     void *_freeres_buf;
>     size_t __pad5;
>     int _mode;
>     char _unused2[15 * sizeof (int) - 4 * sizeof (void *) - sizeof (size_t)];
> };
> ````
>
> 也就是说，这个FILE结构体当中直接保存了底层open打开的文件对象的文件描述符，除此之外该结构体还会保存一些缓冲区状态等信息，这个模型如下图所示：
>
> ![文件流中的文件描述符-图](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403131746448.png#padding#400w)
>
> 了解上述信息后，既然文件描述符直接就是FILE结构体的成员，那么我们就可以直接通过结构体指针操作来获取这个文件描述符成员，代码如下所示：
>
> ```` c
> write(fp->_fileno, "hello", 5);
> ````
>
> 当然你可以思考一个问题：
>
> 这样的操作合适吗？
>
> 虽然这种操作在技术上可行，但这种做法破坏了封装性直接访问到了内部实现细节，而且还缺乏跨平台性(不同平台成员的名字可能不同)
>
> 总之这不是一个好的做法，更好的做法是通过`fileno`函数来获取文件描述符。

# 标准流和重定向

> _~Gn!~_
>
> 在每个进程启动伊始，都会自动打开三个文件流，就是标准输入流stdin、标准输出流stdout、标准错误输出流stderr。
>
> 我们已经知道文件流的底层是文件描述符，那么这些标准流也是一样的，它们的底层分别对应文件描述符：
>
> 1. <span style=color:red;background:yellow>**标准输入流stdin：宏STDIN_FILENO，对应整数值0**</span>
> 2. <span style=color:red;background:yellow>**标准输出流stdout：宏STDOUT_FILENO，对应整数值1**</span>
> 3. <span style=color:red;background:yellow>**标准错误流stderr：宏STDERR_FILENO，对应整数值2**</span>
>
> 我们可以用下列代码来输出它们的文件描述符：
>
> ```` c
> int main(void){
>     printf("stdin = %d\n", fileno(stdin));
>     printf("stdout = %d\n", fileno(stdout));
>     printf("stderr = %d\n", fileno(stderr));
>     return 0;
> }
> ````
> 
>我们已经知道文件流的底层结构体对象中会存储文件描述符，所以每次程序启动，这三个标准流的内存空间都固定存储这三个文件描述符。
> 
>如下图所示：
> 
>![标准流的文件对象-示意图](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/image-20240426233328421.png#padding#400w)
> 
>这三个标准流由C标准库来管理维护，程序员只需要使用它们就可以，不需要考虑它们的内存管理问题。

## close和重定向的原理

> _~Gn!~_
>
> 由于用户空间的标准流结构体对象中固定存储了文件描述符，那么假如我们进行下面的操作：
>
> 1. 先使用`printf`函数向终端输出一句话。<span style=color:red;background:yellow>**（重定向标准输出时，都建议先这么做一下）**</span>
> 2. 然后close文件描述符1(stdout文件对象的描述符)
> 3. 最后重新open一个新的文件，再次调用printf函数打印一句话。
>
> 也就是说，代码如下：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc,2);
>     // 先向终端输出一句话
>     printf("两情若是长久时!\n");
>     close(STDOUT_FILENO); // 关闭文件描述符1
>     // 以读写模式打开一个文件
>     int fd = open(argv[1],O_RDWR);
>     ERROR_CHECK(fd,-1,"open");
>     // 再利用printf函数向标准输出中输出
>     printf("fd = %d\n", fd);
>     printf("又岂在朝朝暮暮!\n");
>     return 0;
> }
> ````
> 
>最终的输出效果是：
> 
>> 屏幕上输出：两情若是长久时!
> >
> > 输出到文件：又岂在朝朝暮暮!
> 
>为什么会这样呢？
> 
>首先，我们要理解一下close的原理：
> 
>close的作用是关闭了一个文件描述符，只有等到某个文件对象的全部文件描述符都被关闭了，才会考虑释放文件对象<span style=color:red;background:yellow>**（引用计数法）**</span>。
> 
><font color=red>**但标准流的文件对象，即便所有文件描述符都被关闭了，但一般操作系统也会继续保留它的文件对象（保留的目的当然是等待重新为标准流文件对象分配文件描述符）。**</font>
> 
>然后，我们还要理解一下open的原理：
> 
>open的作用是打开一个文件，内核会创建文件对象，并分配一个当下<span style=color:red;background:yellow>**可用的最小文件描述符**</span>，返还给用户进程。
> 
>基于这样的原理，我们可以用下图来描绘这个过程：
> 
>![重定向stdout-原理图](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403132122251.png#padding#400w)
> 
>我们之前在给大家讲shell指令中的重定向符号时，也是一直在强调：
> 
><span style=color:red;background:yellow>**重定向不是断开/更改用户进程和标准流缓冲区的连接，而是断开/更改标准流缓冲区到外部设备(屏幕、磁盘等)的连接。**</span>当然，在这里我们更进一步的理解了重定向。
> 
>思考：
> 
>既然能这样重定向标准输出，那么能不能重定向标准输入呢？
> 
>参考下面代码：
> 
>```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>     close(STDIN_FILENO);	// 关闭标准输入流的文件描述符
>     int fd = open(argv[1], O_RDWR);
>     ERROR_CHECK(fd, -1, "open");
>     printf("fd = %d\n", fd);
>     // 此时文件描述符0已经分配给了新打开的一个文件, 也就是说标准输入被重定向到从文件中读数据
>     int a;
>     scanf("%d",&a);		// 把文件中的第一个数字读出来
>     printf("a = %d\n", a);
>     return 0;
> }
> ````
> 
> 原理和上面是一样的。但是我们要注意：<font color=red>**实际应用中几乎不会重定向标准输入，所以我们下面的讲解都会基于标准输出的重定向。**</font>

## dup函数

> _~Gn!~_
>
> 假如我们想要实现重定向功能，比起直接关闭文件描述符然后再open文件，一个更好的办法是使用`dup`函数，这里我们就介绍一下这个函数。
>
> <font color=red>**首先dup这个函数名，缩写自单词"duplicate"，意为复制。**</font>
>
> dup是一个系统调用函数，它的作用就是复制文件描述符。当你使用`dup`函数通过复制已存在的文件描述符，创建一个新的文件描述符时，这个新文件描述符和原始文件描述符就指向了同一个文件对象。
>
> 该函数的声明如下：
>
> ```` c
> #include <unistd.h>
> int dup(int oldfd);
> ````
>
> <font color=red>**形式参数：**</font>`oldfd`：要被复制的文件描述符。
>
> <font color=red>**返回值：**</font>
>
> 1. **成功**：返回新的文件描述符，新文件描述符是当下能够分配的文件描述符的最小值。<span style=color:red;background:yellow>**注意：新的文件描述符和被复制的文件描述符肯定不是同一个整数！但它们会指向同一个文件对象！**</span>
> 2. **失败**：返回 -1，并且设置 `errno` 的值以表示错误原因。
>
> 这个过程如下图所示：
>
> ![dup函数原理-图](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403132226325.png#padding#600w)
>
> 下面我们先简单演示一下这个函数的调用，也就是复制文件描述符：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc,2);
>     // 被复制的文件描述符
>     int old_fd = open(argv[1], O_RDWR);		
>     ERROR_CHECK(old_fd, -1, "open");
>     printf("old_fd = %d\n", old_fd);		// 3
> 
>     // 复制后得到的新文件描述符
>     int new_fd = dup(oldfd);
>     ERROR_CHECK(new_fd, -1, "dup");
>     printf("new_fd = %d\n", new_fd);		// 4
> 
>     // 最终会把helloworld写入同一文件
>     write(old_fd,"Hello", 5);
>     write(new_fd,"World", 5);
> 
>     // 关闭文件描述符
>     close(new_fd);
>     close(old_fd);
>     return 0;
> }
> ````
> 
><font color=red>**首先我们需要注意：这里打印的两个新旧文件描述符，必然是不一样的。这就好比两个指针指向同一个对象，但这两个指针变量本身的地址肯定是不同的。**</font>
> 
>其次dup复制文件描述符的过程，既然可以类比指针指向同一对象，那么使用任一文件描述符修改文件信息，这个修改对于所有文件描述符都是同步的。
> 
><span style=color:red;background:yellow>**并且在这个过程中两个文件描述符，共享同一个文件对象的读写偏移量，也就是共享读写的位置。（因为它们本来就是同一个文件对象）**</span>
> 
>于是最终文件的写入内容是：
> 
>> HelloWorld
> 
>最后思考一个问题：
> 
>close一个文件描述符，内核区域的文件对象会被释放资源吗？
> 
>当然不会，某个文件对象的所有文件描述符都被关闭后，才会释放此文件对象！

## 利用dup函数重定向stdout

> _~Gn!~_
>
> 下面我们来使用dup函数来实现一些常见的，对stdout标准输出的重定向。
>
> 在这个过程中，大家不要过于注重代码，也不要尝试一上来就盯着代码来分析重定向的过程。而是<span style=color:red;background:yellow>**先搞定模型，然后根据模型写代码！**</span>
>
> 下图就展示了一个，利用dup函数展示重定向stdout的过程：
>
> ![重定向stdout-图1](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403132347629.png#padding#600w)
>
> 这个过程用文字描述是：
>
> 1. 第一步是先open一个file文件，此时分配一个fd文件描述符（一般是3）
> 2. 接下来第二步，关闭文件描述符——<font color=red>**1（STDOUT_FILENO）**</font>
> 3. 最后dup复制文件描述符fd（此时分配最小可用的文件描述符，先就是分配1，这样标准输出就被重定向到文件file中了）
> 4. 任何向stdout的输出操作都会最终输出到文件file中。
>
> 整个过程的实现参考代码如下：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc,2);
>     // 先使用printf函数向终端输出一句话
>     printf("我们的爱错过就不再回来!\n");
>     int fd = open(argv[1],O_RDWR);
>     ERROR_CHECK(fd,-1,"open");
> 
>     close(STDOUT_FILENO);
>     // 复制fp文件描述符,但此时给它分配的文件描述符是1，完成重定向操作
>     int fd_cp = dup(fd);
>     // 下面的输出都将输出到文件里
>     printf("fd = %d\n", fd);
>     printf("fd_cp = %d\n", fd_cp);
>     printf("直到现在我还默默得等待!\n");
> 
>         fflush(stdout);		// 在关闭文件描述符释放文件对象之前，刷新一下标准输出缓冲区，避免数据还留在缓冲区中导致数据丢失
>     // 关闭文件描述符
>     close(fd);
>     close(fd_cp);
>     return 0;
> }
> ````
> 
>结合图来一起分析这个过程，还是不困难的。
> 
>注意：这里仍然建议先使用`printf`函数向终端输出一句话。

## dup2函数

> _~Gn!~_
>
> dup2函数和dup一样，都是用来复制文件描述符的系统调用函数。<span style=color:red;background:yellow>**dup2函数的唯一区别是可以自己指定复制后得到的文件描述符的数字。**</span>
>
> 它的函数声明如下：
>
> ```` c
> #include <unistd.h>
> int dup2(int oldfd, int newfd);
> ````
>
> <font color=red>**形参列表：**</font>
>
> 1. `oldfd`: 要被复制的文件描述符，需要是一个已经打开的正在使用的文件描述符。
> 2. `newfd`: 复制后的新文件描述符，此时需要考虑以下情况：
>    1. 如果 `newfd` 已经被程序使用，则 `dup2` 会首先关闭文件描述符 `newfd`，然后再将 `oldfd` 的文件描述符复制到 `newfd`。最终的效果是：`newfd`和`oldfd`都指向原本`oldfd`指向的文件对象。
>    2. 如果 `newfd` 还未被程序使用，那么正常将 `oldfd` 的文件描述符复制到 `newfd`。最终的效果仍然是：`newfd`和`oldfd`都指向原本`oldfd`指向的文件对象。
>
>
> <font color=red>**返回值：**</font>
>
> 1. **成功**：返回新的文件描述符（即 `newfd` 的值）。
> 2. **失败**：返回 -1，并且设置 `errno` 的值以表示错误原因。比较常见的错误就是：传入的 `oldfd` 是一个无效的文件描述符（即它不指向任何打开的文件），那么 `dup2` 将不会执行复制操作，并且会返回错误。在这种情况下，即使 `newfd` 是有效的，`dup2` 也不会关闭它。
>
> 所以这个函数的行为就可以描述成：
>
> `dup2` 同样用于复制文件描述符，和`dup`一样都可以使得两个文件描述符指向同一个文件对象。但它和dup函数的区别是：
>
> 1.  `dup2` 允许指定新文件描述符的具体数值，也就是多了一个参数`newfd`
> 2. <span style=color:red;background:yellow>**当newfd这个文件描述符存在时，dup2会先close这个文件描述符，然后再让newfd和oldfd两个文件描述符都指向oldfd的文件对象。**</span>
> 3. 总之，在正常的情况下，dup2总能保证得到一个指向oldfd文件对象的文件描述符——newfd

## 利用dup2函数重定向stdout

> _~Gn!~_
>
> 利用dup2函数重定向stdout非常简单，如果日常的需求就是简单的重定向stdout，那么推荐选择使用`dup2`函数。
>
> 这个过程参考下图就可以了：
>
> ![重定向stdout-图2](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403132349103.png#padding#600w)
>
> 总共也就只需要两步就可以完成了：
>
> 1. 第一步，先open一个新文件file，分配一个fd文件描述符（此时一般就是3）
> 2. 直接调用dup2函数：`dup(fd, STDOUT_FILENO)`
>    1. 此时的操作是先关闭stdout的文件描述符——1
>    2. 再让文件描述符1指向fd文件描述符指向的文件，这样就完成了重定向到文件的操作。
>
>
> 参考代码实现如下：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc,2);
>     printf("表示从一楼到四楼的距离!\n");		// 先向终端输出一句话
>     int fd = open(argv[1], O_RDWR);
>     ERROR_CHECK(fd, -1, "open");
> 
>     // 关闭标准输出，再让文件描述符1指向fd文件对象，也就是重定向stdout到文件
>     int fd_cp = dup2(fd, STDOUT_FILENO);
>     // 下面的输出都将输出到文件里
>     printf("fd = %d\n", fd);
>     printf("fd_cp = %d\n", fd_cp);
>     printf("原来只有三年!\n");
> 
>     fflush(stdout);		// 在关闭文件描述符释放文件对象之前，刷新一下标准输出缓冲区，避免数据还留在缓冲区中导致数据丢失
>     // 关闭文件描述符
>     close(fd);
>     close(fd_cp);
>     return 0;
> }
> ````
> 
>利用dup2函数相当于将关闭某个文件描述符，和复制文件描述符合并在一起了，代码会变得更简洁高效。
> 
>注意：这里仍然建议先使用`printf`函数向终端输出一句话。

# 结合dup和dup2实现"反复横跳"

> _~Gn!~_
>
> 如果我的需求是：
>
> 先在屏幕上展示一行，再在文件中输出一行，再在屏幕上展示一行，再在文件中输出一行....使得标准输出这样<span style=color:red;background:yellow>**反复横跳**</span>
>
> 应该如何实现呢？
>
> 这个需求实现起来，其实也并不困难，只需要结合dup和dup2一起就可以了。
>
> 模型图可以参考下图：
>
> ![重定向stdout-图3](https://hixiaodong123.oss-cn-hangzhou.aliyuncs.com/typora/202403140011610.png#padding#600w)
>
> 整个过程是：
>
> 1. 第一步，先open一个新文件，分配一个fd文件描述符（一般就是3）
> 2. 第二步，由于要反复横跳，所以需要备份一下stdout文件对象。
>    1. 比如设置一个整数值`int stdout_bak = 7`
>    2. 接下来可以使用`dup2(STDOUT_FILENO, stdout_bak )`，通过这个函数调用完成对标准输入的备份。
> 3. 第三步，直接dup2重定向stdout到文件，代码是：`dup2(fd, STDOUT_FILENO)`
> 4. 第四步，将文件描述符1重新指向stdout文件对象，使得标准输出回归终端设备，代码是：`dup2(stdout_bak , STDOUT_FILENO)`
> 5. ....
>
> 整个过程的参考代码如下：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc,2);
>     printf("叹一句当时\n");			// 先向终端输出一句话
>     int fd = open(argv[1], O_RDWR);
>     ERROR_CHECK(fd, -1, "open");
> 
>     int stdout_bak = 7;
>     dup2(STDOUT_FILENO, stdout_bak);		// 备份stdout文件对象，现在文件描述符7指向它
> 
>     // 重定向标准输出到文件
>     dup2(fd, STDOUT_FILENO);
>     printf("只道是\n");		// 这一句话将输出到文件中
> 
>     // 将文件描述符1重新指向stdout文件对象
>     dup2(stdout_bak,STDOUT_FILENO);
>     printf("寻常!\n");		// 这一句话将输出到终端里
>     // 可以继续进行重定向...回归...
> 
>     fflush(stdout);		// 在关闭文件描述符释放文件对象之前，刷新一下标准输出缓冲区，避免数据还留在缓冲区中导致数据丢失
>     // 关闭文件描述符
>     close(fd);
>     close(stdout_bak);		
>     return 0;
> }
> ````
> 
>这个实现起来实际上也并不困难。
> 
>注意：这里仍然建议先使用`printf`函数向终端输出一句话。

# 扩展：重定向stdout过程中的缓冲区行为

> _~Gn!~_
>
> 在上述重定向stdout标准输出到文件的代码中，我们始终在重定向之前向终端输出了一句话，这是为什么呢？
>
> 为了解答这个疑惑，我们直接来看一段代码：
>
> ```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>        int fd=open(argv[1],O_WRONLY|O_CREAT|O_TRUNC,0664);
>        ERROR_CHECK(fd,-1,"open");
>    
>     //先备份标准输出的文件描述符
>        int temp=dup(STDOUT_FILENO);
>        //将标准输出重定向指向文件
>        dup2(fd, STDOUT_FILENO);
>        printf("How are you?\n");
>        //将标准输出重新终端
>        dup2(temp, STDOUT_FILENO);
>        printf("I'm fine, and you?\n");
>        //再将标准输出重定向到文件
>        dup2(fd, STDOUT_FILENO);
>        printf("Me too.\n");
>    
>     close(fd);
>        return 0;
>    }
> ````
> 
>按照我们的理解，这段代码将使得标准输出在终端和文件之间"横跳"：
> 
>1. "how are u\\n"将在文件中输出
> 2. "I'm fine, and you?\\n"将在终端打印
> 3. "Me too.\\n"又将在文件中输出
> 
><font color=red>**但实际上，这三段文本都将输出到文件，这是为什么呢？**</font>
> 
>这就涉及到操作系统、C标准库对标准输出缓冲区模式的管理了，<span style=color:red;background:yellow>**第一次使用stdout时的上下文（它指向的是终端还是文件）将决定stdout的缓冲区刷新机制，并且在整个进程生命周期，这个刷新机制将默认保持不变：**</span>
> 
>1. 如果第一次使用stdout时它指向一个终端（比如用printf），此时缓冲区就是行缓冲的。
> 2. 如果第一次使用时stdout被重定向到文件或其他非终端设备，缓冲区就变成了满缓冲区，这意味着缓冲区会积累输出直到满了或者手动刷新。
> 
>比如上面的代码：
> 
>虽然重定向都成功了，但由于stdout缓冲区的性质是满缓冲区，所以只能在最终进程结束时，刷新缓冲区，将所有内容全部输出到文件中。
> 
>尝试将代码改成下面的样子：
> 
>```` c
> int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>     int fd=open(argv[1],O_WRONLY|O_CREAT|O_TRUNC,0664);
>     ERROR_CHECK(fd,-1,"open");
> 
>     //先备份标准输出的文件描述符
>     int temp=dup(STDOUT_FILENO);
>     //将标准输出重定向为文件描述符对应的文件
>     dup2(fd, STDOUT_FILENO);
>     printf("How are you?\n");
>     // 手动刷新缓冲区
>     fflush(stdout);
>     //将原来的标准输出文件描述符恢复给标准输出
>     dup2(temp, STDOUT_FILENO);
>     printf("I'm fine, and you?\n");
>     // 手动刷新缓冲区
>     fflush(stdout);
> 
>     //再将文件的文件描述符赋给标准输出
>     dup2(fd, STDOUT_FILENO);
>     printf("Me too.\n");
>     // 手动刷新缓冲区
>     fflush(stdout);
> 
>     close(fd);
>     return 0;
> }
> ````
> 
> 即每一个printf输出后面都加上一个手动刷新缓冲区的`fflush`操作，此时程序的行为将符合大家的预期：
>
> 1. "how are u\\n"将在文件中输出
>2. "I'm fine, and you?\\n"将在终端打印
> 3. "Me too.\\n"又将在文件中输出
> 
> 再来看一段代码：
>
> ```` c
>int main(int argc, char *argv[]){
>     ARGS_CHECK(argc, 2);
>     int fd=open(argv[1],O_WRONLY|O_CREAT|O_TRUNC,0664);
>     ERROR_CHECK(fd,-1,"open");
> 
>     // 先printf输出一句话
