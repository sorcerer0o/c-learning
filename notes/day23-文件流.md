# Day23 - 文件流: 有缓冲与无缓冲

## ISO-C 与 POSIX

| | ISO-C 标准 | POSIX 标准 |
|---|---|---|
| 代表函数 | fopen / fread / fwrite | open / read / write |
| 跨平台 | 任何有 C 编译器的平台 | 仅类 Unix 系统 |
| 实现方式 | 库函数 | 系统调用 (需调用内核) |

- 文件系统的**系统编程**操作, 因为需要调用内核, 所以只能在类 Unix 中实现
- 标准 C 库函数底层在 Linux 上最终也是基于系统调用实现的 (如 fopen 底层是 open)

## 系统调用函数的学习步骤

1. 记住函数名、大致功能, 推测传入/传出参数、返回值等
2. 记牢 man 手册卷号: **卷 2 = 系统调用**, **卷 3 = 库函数**
3. 打开函数 man 手册, 按顺序看:
   - 先看 **NAME**: 函数基本作用
   - 再看 **SYNOPSIS**: 头文件 → 函数声明 → 返回值

## 函数设计规律 (错误处理核心)

### 为什么返回值如此重要
- C 语言**缺乏错误检查机制**, 函数执行出错只能依赖返回值判断
- 返回值是什么 → 决定程序应如何做错误处理

### 返回值规律
- 返回值通常**兼具两个任务**:
  1. 正常返回值 (业务语义)
  2. 出错标记
- 所以先检查返回值是否为 **-1 / NULL**, 再谈业务

### 参数规律
- 指针参数若加 `const` → 该入参是**只读参数** (函数不会修改)
- 指针参数若**没有** `const` → 大概率会被函数修改 (传出/传入传出)
- 例: `write(fd, buf, n)` 的 buf 带 const (只读), `read(fd, buf, n)` 的 buf 不带 (会被写入)

### xx_t 类型别名
- `_t` 结尾的类型 (如 `mode_t`, `off_t`, `size_t`, `ssize_t`, `nlink_t`) 是**类型别名** (typedef)
- 作用: 屏蔽平台差异, 增强可移植性
- 查看别名/结构体定义: 预处理成 .i 文件后 grep, 或查 man 手册

## 复习 sprintf / snprintf (字符串拼接)

- `sprintf(buf, fmt, ...)`: 格式化写入字符串, 常用于拼接路径
- `snprintf(buf, size, fmt, ...)`: 限定了最多写入 size 字节, **防止缓冲区溢出**, 优先使用

## 有缓冲文件流 (C 标准库回顾)

- 即操作 **FILE\* 指针** 的那一套方案 (fopen/fread/fwrite...)
- 更准确称呼: **带有用户态缓冲区的文件流** (目录流也属于此类)

### 用户态缓冲区原理
- 标准 C 库在**用户内存空间**预留一段缓冲区, 减少 IO 次数 → 减少系统调用次数 → 提升效率
- 缓冲区相当于"二道贩子":
  - **读**: 一次性从内核缓冲区读"一大块"数据到用户态缓冲区, 进程再小块取用
  - **写**: 进程先写入用户态缓冲区, "积攒"够一大块再一次性写入内核缓冲区
- 数据流向:
  - 读: 磁盘 → 内核态缓冲区 → 用户态缓冲区 → 用户进程
  - 写: 用户进程 → 用户态缓冲区 → 内核态缓冲区 → 磁盘
- **系统调用代价昂贵**: 需用户态↔内核态切换, 所以减少系统调用次数 = 提升 IO 效率

## 无缓冲文件流 (重点)

- 精确描述: **无用户态缓冲区, 用户进程直接和内核态缓冲区进行系统调用交互**

### 文件描述符 (fd) 概念
- 内核缓冲区不能直接给用户进程指针 (太危险, 会破坏内核空间安全)
- 内核维护"索引指针数组", 存放文件对象的地址; 数组下标从 0 开始
- **文件描述符 = 索引数组的下标** (非负整数, 最大 1024)
- 流程:
  1. open 文件 → 内核创建文件对象
  2. 内核将索引指针数组元素下标返还给用户进程 → 得到 fd
  3. 用户进程通过 fd 与内核进行系统调用级交互
- 全程用户进程**未获得内核任何地址** → 保证系统安全稳定

### 标准流: 0 / 1 / 2
- 进程启动时系统自动打开三个特殊文件描述符:
  - `0` 标准输入 stdin (默认键盘)
  - `1` 标准输出 stdout (默认屏幕)
  - `2` 标准错误 stderr (默认屏幕)
- 外部设备被视为设备文件 → 体现 Linux 设计哲学**万物皆文件** (见 /dev)

### open 函数
```c
#include <fcntl.h>
#include <sys/types.h>
#include <sys/stat.h>
int open(const char *pathname, int flags);
int open(const char *pathname, int flags, mode_t mode);
```
- 成功: 返回文件描述符 (非负整数); 失败: 返回 -1 并设置 errno
- 注意: C 不支持函数重载, 两参/三参形式是历史遗留

### flags 参数 (重点)
- flags 是 32 位整数, 每个标志对应位模式中某一位为 1
- 三个标志**固定占低两位**, 且**互斥, 必须三选一**:
  - `O_RDONLY` = 0 只读
  - `O_WRONLY` = 1 只写
  - `O_RDWR` = 2 读写

| 标志 | 含义 | 注意 |
|---|---|---|
| O_RDONLY | 只读 | 三选一 |
| O_WRONLY | 只写 | 三选一 |
| O_RDWR | 读写 | 三选一 |
| O_CREAT | 文件不存在则创建 | **不加则文件不存在时打开失败** |
| O_EXCL | 文件已存在则 open 失败 | **仅与 O_CREAT 连用** |
| O_TRUNC | 打开时清空文件内容 (截断为 0) | 需以写模式打开 |
| O_APPEND | 追加模式 | 不与 O_RDONLY/O_TRUNC 连用 |

- 其余标志互不冲突, 用**按位或 `|`** 拼接:
  - `O_WRONLY | O_CREAT | O_EXCL`: 只写 + 不存在则创建 + 已存在则报错 (防覆盖)
  - `O_RDWR | O_CREAT | O_TRUNC`: 读写 + 创建 + 清空, 类似 fopen 的 "w+"

### mode 参数
- 仅在使用了 **O_CREAT** 时必带 (三参形式), 用于指定新建文件权限 (八进制如 0666)
- 没有 O_CREAT 时**不要**带该参数
- 实际权限受 umask 影响 (0666 & ~umask)

### fopen 与 open 的关系
- fopen 的各个打开模式 ("r"/"w"/"a"/"w+"...) 底层就是基于 open 的标志组合实现的 (`man 3 fopen` 可查)

### close 函数
```c
#include <unistd.h>
int close(int fd);
```
- 成功返回 0, 失败返回 -1
- **注意**: close 表示关闭文件描述符, 不是立刻释放文件对象资源 (细节后面小节补充)

### read 函数
```c
#include <unistd.h>
ssize_t read(int fd, void *buf, size_t count);
```
- 参数: fd 文件描述符; buf 接收数据的用户内存区; count 最多读取字节数
- 返回值:
  - `> 0`: 实际读到的字节数 (可能小于 count)
  - `0`: 到达文件末尾 (EOF)
  - `-1`: 出错, errno 指示错误类型

### 非阻塞 read: 读硬盘文件
- 读磁盘文件是**非阻塞**的: 读到末尾后继续 read 不阻塞, 直接返回 0
- 因此可用 `while ((n = read(fd, buf, sizeof(buf)-1)) > 0)` 循环读完整个文件

```c
char buf[6] = { 0 };
ssize_t read_count;
while ((read_count = read(fd, buf, sizeof(buf) - 1)) > 0) {
    printf("read_count = %ld, buf = %s\n", read_count, buf);
    memset(buf, 0, sizeof(buf));   // 清空缓冲区避免脏数据
}
ERROR_CHECK(read_count, -1, "read");
```
- `memset(buf, 0, sizeof(buf))`: 将内存块所有字节设为指定值 (常用来清零缓冲区, 避免读到上次残留的脏数据)

### 阻塞 read: 读设备文件
- 设备文件 (键盘、网络套接字) 的 read **一般是阻塞的**: 没有数据时进程挂起等待
- 如果用循环读设备文件, 数据不来 → 永远等不到返回 0 → **阻塞死循环**
- 例: `read(0, buf, sizeof(buf))` 从键盘读
- 磁盘文件: 确定性、数据持久; 设备文件: 不确定性、依赖外部因素 (为后续课程打基础)

### write 函数
```c
#include <unistd.h>
ssize_t write(int fd, const void *buf, size_t count);
```
- 参数: fd 文件描述符; buf 待写出的数据 (const, 只读); count 写入字节数
- 返回值: 成功返回实际写入字节数 (通常等于 count); 失败返回 -1

```c
int fd = open(argv[1], O_RDWR);
ERROR_CHECK(fd, -1, "open");
ssize_t sret = write(fd, "howareyou", 9);   // 写入 9 个字节
close(fd);
```

### read / write 对比

| | read | write |
|---|---|---|
| buf 参数 | 无 const (会被修改) | 有 const (只读) |
| count 含义 | 最大读取字节数 | 需写出的字节数 |
| 返回值 | 可能小于 count | 通常等于 count |

## ftruncate 截断文件

```c
#include <unistd.h>
int ftruncate(int fd, off_t length);
```
- 改变已打开文件的大小 (可增大可减小):
  - 增大: 新增部分用**零字节**填充
  - 减小: 从末尾**截断**, 丢弃超出的数据 (不可恢复)
- 成功返回 0, 失败返回 -1

### 文件空洞
- stat 指令: `Size` 文件实际大小; `Blocks` 文件占用的 512 字节磁盘块数
- 磁盘以 4096 字节 (8 块) 为最小分配单位 → 一般占盘空间 ≥ 文件大小
- 但用 ftruncate 分配特别大的字节数时, 文件大小 > 实际磁盘占用 → 中间未真正分配磁盘块, 即**文件空洞**
- 作用: 快速占位 (文件系统分配快, 磁盘真正分配慢)
- 经典场景: **下载前预先用 ftruncate 分配空间**, 避免下载中途磁盘不足
